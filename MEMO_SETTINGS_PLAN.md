# Управление содержанием памятки через Google Таблицу

Подготовка к следующему этапу. Файл `memo-settings-template.csv` — **шаблон**, а не действующая конфигурация. Пока он ни на что на сайте не влияет.

## План

1. После согласования с владельцем рабочей таблицы создать отдельную вкладку **Настройки памятки** (или отдельную таблицу управления, если менять исходную нельзя).
2. Внести туда четыре обязательных поля: `section_id`, название раздела, `Показывать` (`ДА`/`НЕТ`), `Порядок`. Для новых разделов указать вкладку-источник.
3. Согласовать видимость контактов сотрудников: вкладка **Контакты банков** по умолчанию имеет `НЕТ`.
4. Доработать генератор данных с полной пересборкой карточек из строк источника и защитой от случайного удаления или пустой выдачи.
5. Проверить добавление банка, изменение ставки, удаление банка, перемещение раздела, скрытие и добавление вкладки. После проверки включить расписание.

## Текущий режим

Workflow `.github/workflows/sync-bank-memo.yml` запускается **только вручную**, по умолчанию в режиме просмотра без записи в GitHub. Даже подтверждённый режим публикации пока не является проверенной полной структурной синхронизацией: скрипт обновляет известные значения по совпадениям. Публиковать новую версию до завершения сопоставления всех вкладок не следует.

**Безопасность:** исходный репозиторий публичный. Настройки публичного сайта не являются защитой для персональных данных: контактные сведения, уже сохранённые в `memo-data.js`, остаются доступными из исходного кода. Для внутренних контактов потребуется отдельное ограниченное решение.

## Созданная управляющая Google Таблица

**Управление памяткой — Банки России 3.0**

https://docs.google.com/spreadsheets/d/14YwnO6gXtAm_mkWdV194QLJ51ajP3e9jC3L-1NQDR9s/edit

Вкладки: **Разделы памятки**, **Инструкция**. Внесены 21 существующий раздел и одна тестовая отключённая строка нового раздела `new-01`.

Для каждой записи определены:
- `ID раздела` — постоянный уникальный идентификатор; не менять в уже созданных разделах;
- `Название на сайте` — подпись в меню;
- `Показывать` — `ДА`/`НЕТ`, безопасное скрытие без удаления;
- `Порядок` — порядок сортировки;
- `Группа` — группа оригинального меню;
- `Вкладка-источник` — точное название вкладки в исходной Google Таблице;
- `Тип данных` — `Исходный формат` или `Авто: таблица`;
- `Статус` — пояснение для редактора.

Сервисному аккаунту `mortgage-sheets-sync@pamyatkaipoteka.iam.gserviceaccount.com` предоставлены права **reader** на эту управляющую таблицу. Основной исходный файл не изменён.

**Важно:** это подготовленная рабочая таблица настроек, но существующий синхронизатор ещё НЕ считывает её. Сайт продолжает показывать прежние 21 раздел без изменений.

## Правила будущего синхронизатора для добавления и удаления разделов

1. Всегда загружать управляющую таблицу отдельно от основной; требовать уникальные ID и существующие вкладки-источники.
2. Существующие разделы `Исходный формат` сохранять без изменения их схемы. Обрабатывать `Показывать`, `Порядок`, название и группу; при `НЕТ` не включать в публичные данные и навигацию.
3. Новый раздел `Авто: таблица` можно создать только после проверки простой прямоугольной структуры с единственной строкой заголовка. Сложные матрицы/объединённые заголовки — блокировать публикацию до настройки адаптера, а не публиковать искажённую таблицу.
4. Строка `НЕТ` означает скрытие раздела без удаления строки из исходных данных; отсутствие строки, пустой лист или ошибка API не должны восприниматься как приказ удалить всё.
5. Проверять наличие содержимого, непротиворечивость формата, число строк, неожиданные массовые удаления и отсутствие персональных данных перед публикацией.
6. По умолчанию запуск в режиме просмотра без записи; расписание включать только после сценарных проверок и проверки оригинального интерфейса.
